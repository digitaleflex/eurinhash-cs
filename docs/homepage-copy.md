# Homepage Copy — Eurin Hash

> Issue: #58  
> Depends on: #56 Brand Voice, #57 Messaging Architecture  
> Branch: `foundation/20-20-reset`

## 1. Objectif

La homepage doit permettre à un visiteur de comprendre rapidement :

1. qui est Eurin Hash ;
2. quels problèmes il sait résoudre ;
3. comment il intervient ;
4. quelles preuves rendent son positionnement crédible ;
5. quelle action peut être engagée ensuite.

La homepage ne doit pas présenter Eurin comme un catalogue de technologies ni comme une agence générique.

# 7. Méthode

## Eyebrow

**UNE MÉTHODE SIMPLE**

## H2

**Comprendre avant de construire.**

### 01 — Comprendre

Clarifier le problème, les utilisateurs, les contraintes et les priorités.

### 02 — Simplifier

Réduire la complexité inutile et distinguer ce qui est essentiel de ce qui ne l’est pas.

### 03 — Concevoir

Définir l’architecture, les responsabilités, les flux et les choix techniques.

### 04 — Construire

Implémenter uniquement ce qui est nécessaire pour produire une solution exploitable.

### 05 — Sécuriser

Traiter les chemins critiques, les accès, les données et les risques opérationnels.

### 06 — Valider

Tester, mesurer, documenter et confronter les hypothèses au système réel.

# 11. Claims à supprimer

Les formulations suivantes ne doivent plus apparaître sans preuve explicite :

- « croître sans limites »
- « fiabilité totale »
- « zéro risque »
- « sécurité absolue »
- « souveraineté 100 % »
- « hautement sécurisé » lorsqu’aucune définition ni preuve n’est donnée
- « disponibilité sans compromis »
- « état du protocole : optimal »
- « norme ISO 27001 conforme » sans certification ou périmètre documenté
- « mentorat d’élite »
- « recrutement d’élite »
- « excellence » comme preuve en soi
- « architecture souveraine » lorsqu’elle n’est pas expliquée
- toute statistique non vérifiable ou sans période/périmètre

# 12. Règles UX copy

## Une section = une fonction

- Hero → identité + valeur
- Preuve → crédibilité
- Expertise → capacité
- Réalisations → évidence
- Méthode → réduction de l’incertitude
- About → contexte humain et professionnel
- Insights → démonstration de pensée
- CTA → prochaine action

## Une action primaire par section

Éviter les répétitions de « Contactez-moi », « Réserver », « Découvrir », etc. lorsque la page dispose déjà d’une action plus pertinente.

## Claims proches des preuves

Plus une affirmation est forte, plus sa preuve doit être proche.

## Spécificité > adjectifs

Préférer :

> « Audit, durcissement et sécurisation des flux »

à :

> « Solutions de cybersécurité ultra-performantes et innovantes »

## Verbes > slogans

Préférer :

> concevoir, analyser, structurer, construire, sécuriser, automatiser, valider

à :

> révolutionner, transformer le monde, repousser les limites, disrupter

# 14. Definition of Done

La homepage est considérée comme terminée lorsque :

- [ ] L’identité d’Eurin est comprise en moins de 5 secondes.
- [ ] Le H1 porte une seule idée forte.
- [ ] Le sous-titre explique concrètement la valeur.
- [ ] Les anciennes promesses absolues ont disparu.
- [ ] Les statistiques décoratives sont supprimées ou prouvées.
- [ ] Les services sont exprimés par problèmes/capacités, pas par une liste de technologies.
- [ ] Les réalisations montrent contexte, intervention, décisions et résultat/état.
- [ ] Les CTA sont cohérents avec l’intention de chaque section.
- [ ] Le contenu reste compréhensible pour un décideur non technique.
- [ ] Les détails techniques restent disponibles pour les visiteurs techniques.
- [ ] Aucun contenu fictif n’est présenté comme une preuve.
- [ ] La page respecte la voix définie dans #56.
- [ ] La hiérarchie définie dans #57 est respectée.
- [ ] Le contenu fonctionne sur mobile sans perte de compréhension.
- [ ] Le contenu reste crédible même sans animation.
