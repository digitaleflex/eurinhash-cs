# Trust & Proof System

## Règle centrale

Toute affirmation importante du site doit être soit :

- vérifiable par une réalisation ou un livrable ;
- soutenue par une donnée mesurée ;
- soutenue par une expérience clairement attribuée ;
- formulée comme une approche, une opinion ou un objectif.

## Types de preuves acceptés

| Preuve | Usage |
|---|---|
| Étude de cas | Montrer le raisonnement et l’exécution |
| Repository | Vérifier une implémentation publiable |
| Démo | Vérifier un comportement |
| Résultat mesuré | Quantifier uniquement ce qui a été réellement mesuré |
| Expérience professionnelle | Contextualiser une compétence |
| Formation / certification | Ajouter un signal lorsque pertinent |
| Témoignage authentique | Ajouter de la preuve sociale avec contexte |

## Claims interdits sans preuve indépendante

- zéro risque ;
- sécurité absolue ;
- 100 % souveraineté ;
- disponibilité garantie ;
- meilleur / numéro 1 ;
- expert reconnu ;
- conformité à une norme sans périmètre et preuve ;
- compteurs ou statistiques décoratives.

## Proximité de la preuve

Plus une affirmation est forte, plus sa preuve doit être proche. Une preuve générique placée loin de la promesse ne suffit pas.

## Résultats vs intentions

Un objectif, une recommandation ou une architecture cible ne doit jamais être présenté comme un résultat obtenu.

Quand une métrique n’est pas disponible, écrire explicitement que le résultat quantitatif n’a pas été mesuré ou n’est pas publié.
