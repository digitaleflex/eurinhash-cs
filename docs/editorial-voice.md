# Editorial Voice — Eurin Hash

## Purpose

Le contenu public doit renforcer le même positionnement : **Software Architect · Digital Entrepreneur · AI & Cybersecurity**.

Le blog n’est pas un flux SEO. Il sert à montrer comment Eurin raisonne face à des problèmes techniques réels.

## Piliers

1. Architecture logicielle
2. IA appliquée
3. Cybersécurité
4. Cloud / DevOps
5. Retours d’expérience
6. Décisions techniques et trade-offs

## Template d’article

1. Question ou problème
2. Contexte
3. Hypothèse / point de vue
4. Analyse
5. Preuves, expérience ou expérimentation
6. Conclusion
7. Prochaine lecture ou action

## Publish / Revise / Reject

### PUBLISH
- apporte une idée, une expérience ou une analyse originale ;
- distingue les faits, hypothèses et opinions ;
- contient suffisamment de contexte pour être utile ;
- reste cohérent avec le positionnement professionnel.

### REVISE
- sujet pertinent mais preuve insuffisante ;
- structure confuse ;
- titre trop générique ;
- jargon non nécessaire ;
- conclusion sans implication pratique.

### REJECT
- contenu générique ou généré en série sans apport ;
- article publié uniquement pour remplir un calendrier ;
- claims impossibles à vérifier ;
- sujet hors territoire éditorial sans raison claire.

## Règles de voix

Précis, calme, direct, technique sans obscurité, confiant sans arrogance.

Éviter les superlatifs et les promesses absolues. Les technologies sont des moyens d’exécution, pas le message principal.

## Gouvernance

Un article peut rester non publié. La fréquence n’est pas un KPI éditorial. La valeur apportée au lecteur prime.
